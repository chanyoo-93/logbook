# Phase 9 보완: 보고서 옮겨 적기 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 금요일 오후에 보고서를 회사 양식(엑셀·한글)으로 옮기는 마지막 단계를 짧게 만든다.

2026-10-26 웹 전 화면 평가(26/40)의 P1이다. 지금 보고서 화면의 문제는 다음과 같다.
- Markdown 원문 `<pre>`만 있어서 공수 표가 `|`·`|---|` 문자 그대로 보인다.
- 복사는 전체 한 덩어리이고, 붙이면 셀로 나뉘지 않는다.
- `(작성하세요)` 같은 자리표시 문구가 복사본에 섞인다.
- 복사·내려받기는 글자 없는 아이콘이다.
- 특이사항을 저장하기 전에는 미리보기에 반영되지 않는데, 이를 알려 주지 않는다.

**기준:** develop ad55c43(PR #29 병합)에서 갈라진 브랜치 `feat/report-transcribe`

**진행:**
- 계획서 승인 → Task 순서대로 진행한다. 테스트를 먼저 써서 실패를 확인(RED)한다.

- 끝에 문서·전체 검증·최종 리뷰 1회(`final-reviewer`, Sonnet high) → PR(develop) → "logbook QA" 세션 자동 점검.
- 구현은 메인 세션이 직접 한다.

**Tech Stack:** 기존과 같다. 새 의존성은 없다.
- 표 보기는 Jinja 부분 템플릿으로 서버에서 그린다.
- 전환·복사·저장 안내는 `static/js/report.js`를 확장한다. 외부 파일이라 CSP 그대로이고, 인라인 스크립트·스타일은 쓰지 않는다.

**R1 자세히**
- 표 보기는 보고서 데이터(`ReportData`)로 그린다. 공수 요약은 진짜 표이고, 프로젝트별 실적·다음 주 계획·부록은 목록이다.
- 사용자 보고서 템플릿을 쓰면 그 결과는 `원문`에만 반영되고, 표 보기는 기본 구조 그대로다.
- 사용자 템플릿에 오류가 있어도 표 보기는 볼 수 있다. 지금은 오류면 미리보기가 통째로 없다.
- 마지막으로 고른 탭을 브라우저에 기억한다(`localStorage`, try/catch, 실패하면 표 보기).

**R2 자세히**
- 클립보드에 `text/html`과 `text/plain` 두 형식을 함께 넣는다.
  - 엑셀·한글에 붙이면 표가 셀로 나뉜다.
  - 메모장·메신저에 붙이면 표는 탭으로, 목록은 줄로 구분된 글이 된다.
- 표 보기에는 절마다 `복사` 버튼, 맨 위에 `전체 복사`가 있다. `원문` 탭에는 `Markdown 복사`가 있다.
- 복사·내려받기 버튼은 아이콘과 글자(`복사`, `전체 복사`, `Markdown 복사`, `내려받기`)를 함께 보인다.

**R3 자세히**
- 대상 문구: `(작성하세요)`, `계획된 태스크가 없습니다.`, `기록이 없습니다.`
- `원문`, 내려받기, `lb report`는 그대로다.

**R4 자세히**
- 입력이 저장된 값과 달라지면 폼에 `저장하지 않은 변경이 있습니다. 저장해야 보고서에 들어갑니다.`를 보인다.
- 그 상태로 복사하면 복사 결과 줄에도 같은 경고를 덧붙인다.
- 페이지를 떠날 때 띄우는 확인창은 쓰지 않는다.

## Task 1: 표 보기와 원문 탭 (R1, R5)

**파일**
- `web/pages/report.py`: `ReportBodyView`에 보고서 데이터 `sheet`를 더한다.
- `templates/partials/report_sheet.html`(새 파일)
- `templates/partials/report_body.html`
- `static/css/report.css`
- `static/js/report.js`(탭)
- `tests/web/test_report_page.py`

**구성**
- 머리: 제목, 작성자, 기간(`2026-W44 · 10-26 ~ 11-01`).
- 1. 공수 요약: 총계 한 줄과 표.
  - 열은 프로젝트, 카테고리들, 합계, 비율이다.
  - 숫자 열은 오른쪽 정렬이다.
  - 마지막에 카테고리별 합계 행을 둔다(R6, 웹에서 계산).
- 2. 프로젝트별 실적: 표(R7). 열은 프로젝트 · 상태 · 태스크(`제목 #ID`) · 실적 · 예상이고, 프로젝트 머리 행에 합계, 기타는 마지막 행이다.
- 3. 특이사항 / 리스크: 저장된 글을 줄바꿈 그대로 보인다.
- 4. 다음 주 계획: 표(R7). 열은 프로젝트 · 태스크 · 예상 · 비고(`이월 후보`)이고, 프로젝트 머리 행에 예상 합계다.
- 부록. 커밋 내역: 있을 때만.
- 빈 절은 자리표시 문구를 흐린 글자로 보이고, `data-copy-skip`을 붙인다(R3).
- 탭은 `role="tablist"`와 `tab`·`tabpanel`, `aria-selected`, `hidden` 속성으로 만든다. 좌우 화살표로 탭을 이동한다. 탭 아래 원문 설명 한 줄(R9). JS가 없으면 탭 없이 표 보기와 그 아래 접힌 원문(`<details>`)이 보인다.

**테스트 먼저(RED)**
- 표 보기에 절 4개(커밋이 있으면 5개)의 제목이 있는지.
- 공수 표의 머리글·셀·합계가 데이터와 같은지.
- 빈 절에 자리표시 문구와 `data-copy-skip`이 있는지.
- 탭 마크업(`role`, `aria-controls`, 기본 선택 = 표 보기)이 맞는지.
- 사용자 템플릿 오류 때도 표 보기가 있는지.

**확인:** 보고서 1280·375·320 × 밝은·어두운 전후 스크린샷. 데이터가 있는 주와 빈 주를 모두 본다.

## Task 2: 절별·전체 복사와 글자 있는 버튼 (R2, R3)

**파일:** `report_sheet.html`, `report_body.html`, `static/js/report.js`, `report.css`, 테스트

**버튼**
- 절마다 `복사`(`data-copy-section`), 표 보기 맨 위에 `전체 복사`, 원문 탭에 `Markdown 복사`, 머리 동작에 `내려받기`(아이콘+글자).
- 문장 다듬기 버튼은 그대로 둔다.

**복사 방식**
- 대상 요소를 복제하고 `data-copy-skip` 요소를 지운 뒤 두 형식을 만든다. HTML은 표·목록 그대로, 글은 표를 탭·줄바꿈으로, 목록을 `- ` 줄로 만든다.
- 넣는 방법:
  - `navigator.clipboard.write([new ClipboardItem({"text/html", "text/plain"})])`
  - 실패하면 복제본을 화면 밖에 붙여 선택한 뒤 `execCommand("copy")`. 이 방식도 서식이 함께 복사된다.
  - 그것도 실패하면 기존 실패 문구.
- 결과 줄: `공수 요약을 복사했습니다.`, `보고서 전체를 복사했습니다.`처럼 무엇을 복사했는지 말한다.

**테스트 먼저(RED):** 버튼마다 글자와 `aria-label`, 대상 id가 있고, 대상이 실제로 있는지. JS 동작은 Edge 헤드리스 CDP로 확인한다(클립보드 권한을 주고 `navigator.clipboard.read()`로 두 형식을 읽음). 가능하면 QA 세션 점검에도 넣는다.

**확인**
- 엑셀·한글 붙여 넣기는 사용자 손 확인 항목으로 둔다.
- 헤드리스에서는 클립보드의 HTML 표 구조와 글의 탭 구분을 확인한다.
