# Phase 2 구현 계획 (CLI — 기록 중심)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `core.services` 위에 다음 명령을 구현한다.
- `lb init`, `lb project add|list|archive`
- `lb add`
- `lb log`와 `lb log edit|rm`
- `lb stats`

Windows와 macOS에서 한글 출력, 인자 처리, DB 오류가 같은 결과를 내도록 두 종류의 테스트로 고정한다.
- CliRunner 테스트
- 실제 `lb` 실행 파일을 띄우는 회귀 테스트

`lb add` 응답 시간은 먼저 실측하고, SPEC 8의 목표는 그 결과를 보고 사용자가 다시 정한다(계획 안에서 바꾸지 않는다).

**Architecture:**
- **진입점:** `run()`이 Click이 인자를 파싱하기 전에 `ensure_utf8_console()`을 부르고, 이어서 `app(prog_name="lb", windows_expand_args=False)`를 실행한다.
- **오류 처리:** 루트 `LogbookGroup.invoke` 한 곳이 `LogbookError`를 stderr의 `오류: …` 한 줄(exit 1)로 바꾼다. 출력 파이프가 닫힌 경우도 같은 곳에서 처리한다.
- **import:** 명령 모듈은 상단에서 `typer`만 import한다. `core.config/db/services`와 `rich`는 함수 안에서 지연 import한다.
- **DB 진입:** 일반 명령은 core의 새 진입점 `db.open_database()`로만 연다. `lb init`만 `db.initialize_database()`를 쓴다.
  - 파일이 없거나 비었으면 파일을 만들지 않고 `lb init`을 안내한다.
  - 스키마 버전은 한 번만 읽고, 낮을 때만 대기 중인 마이그레이션을 적용한다.
  - SQLite 잠금, 권한, 용량 오류는 core에서 한국어 `LogbookError`로 바꾼다.
- **출력:**
  - Rich Console에서 마크업, 이모지, 하이라이트를 끈다.
  - 사용자 데이터는 항상 `rich.text.Text`로 감싼다.
  - 터미널이 아니면(파이프, 파일, 테스트) 폭을 `PIPE_WIDTH = 1000`으로 고정하고 `legacy_windows=False`를 쓴다. 그래서 두 OS가 같은 바이트를 내고, 기록 한 건이 한 줄로 유지되어 `grep`·`Select-String`으로 걸러진다.
  - 좁은 터미널에서는 표에 필요한 폭을 직접 계산해, 모자라면 표 대신 한 줄 목록을 출력한다.

**Tech Stack:** Python 3.11+(CI는 3.12), uv, Typer 0.27(Click 내장), Rich 15, SQLAlchemy 2.1, pytest + pytest-cov, ruff, mypy(strict는 core만, CLAUDE.md 규칙 유지). 새 의존성은 없다.

## CLI 공통 규칙 (Task 2-4 ~ 2-9에 모두 적용)

### CLI가 부르는 core API
| 모듈 | CLI에서 쓰는 것 |
|---|---|
| `core.services` | 도메인 유스케이스 전부(프로젝트, 기록, 집계) |
| `core.db` | `open_database`, `session_scope`(둘 다 `runtime.session`에서만), `initialize_database`, `InitResult`(`lb init`에서만) |
| `core.config` | `config_path`, `load_config`, `write_default_config` |
| `core.duration`, `core.weeks` | 입력 파싱(`parse_duration`, `parse_date`, `parse_week`)과 표기(`format_duration`, `day_label`, `week_heading`) |
| `core.platform`, `core.errors` | `ensure_utf8_console`, `symbol`, 오류 클래스 |

CLI에는 SQL·ORM 쿼리, `sqlalchemy` import, 모델 객체를 직접 만들거나 고치는 코드를 쓰지 않는다. CLAUDE.md의 "CLI와 Web은 반드시 core.services의 함수만 호출한다"를 이렇게 해석하고, Task 2-12에서 이 목록을 CLAUDE.md와 AGENTS.md에 한 줄로 적는다.

### 명령 본문의 실행 순서
1. DB와 설정 없이 끝낼 수 있는 변환과 검증을 먼저 한다: `parse_duration`, `runtime.parse_id`, 옵션 조합 검사, `--by` 값 검사. 여기서 실패하면 SQLAlchemy를 로드하지 않고 끝난다.
2. `cfg = runtime.settings()`로 설정을 읽는다(`load_config()`, `LOGBOOK_CONFIG`와 `LOGBOOK_DB` 반영).
3. 설정이 필요한 변환을 한다: `parse_date(text, today=runtime.today(), week_start=cfg.week_start)`, `parse_week(...)`. 서비스에는 `work_date`와 `today`를 항상 명시해 넘긴다. 자정 경계에서 CLI와 서비스가 보는 '오늘'이 어긋나지 않게 하려는 것이다.
4. `with runtime.session(cfg) as s:` 안에서 `services.*`만 호출한다.
5. 세션을 닫은 뒤 출력한다. `expire_on_commit=False`와 joinedload 덕분에 관계 속성을 세션 밖에서도 읽을 수 있다.

추가 규칙:
- **문자열로 받는 인자:** 시간, 날짜, 주차, ID, `-t`, `--by`는 모두 `str`로 받는다.
  - Typer의 `parser=`, `callback=`, `int` 타입, `Literal` 타입은 쓰지 않는다.
  - `InvalidInputError`는 `ValueError`의 하위 클래스라서 Click이 잡아 영어 "Invalid value for …"로 바꿔 버린다. `int`로 받으면 'is not a valid int'라는 영어 오류가 난다.
- **생략 판정은 `is not None`:** 옵션을 줬는지는 항상 `is not None`으로 판정한다.
  - `on or "today"`처럼 참거짓으로 쓰면 `-d ""`가 조용히 오늘이 되고, `-w ""`는 이번 주, `--by ""`는 행렬이 된다.
  - 빈 문자열은 그대로 core 파서와 서비스로 넘겨 한국어 형식 오류가 나게 한다(예: `날짜 형식이 올바르지 않습니다: ''. …`).
- **옵션 이름 명시:** 표에 적힌 옵션 이름(`--all/-a`, `--minutes/-m`, `--note/-n`, `--no-task`)과 매개변수 이름이 다르면 `Annotated[..., typer.Option("--all", "-a")]`처럼 이름을 직접 준다.
  - 기본값만 쓰면 Typer가 `--include-all/--no-include-all`, 짧은 이름 없음, `--no-task/--no-no-task`를 만든다.
  - bool 플래그는 이름을 하나만 주어 `--no-…` 짝이 생기지 않게 한다(Typer 0.27.2에서 확인함).
- **today 주입:** 명령은 `from logbook.cli import runtime` 뒤 `runtime.today()`로 부른다. 테스트가 monkeypatch하는 단일 지점이다.
- **그룹 콜백:** `lb log` 목록을 제외한 그룹 콜백에서는 설정이나 DB에 접근하지 않는다. 콜백은 하위 명령의 `--help`와 인자 검증보다 먼저 실행되기 때문이다.
- **UTF-8 설정 위치:** `ensure_utf8_console()`은 `run()`에서만 부른다. 명령이나 콜백 안에서 부르면 CliRunner의 스트림까지 바뀐다.

### import 규칙 (지연 import, 결정 2 대응)
| 위치 | 허용 대상 |
|---|---|
| CLI 모듈 상단 | `typing`, `contextlib`, `datetime`, `errno`, `os`, `sys`, `typer`, `logbook.__version__`, `logbook.core.errors`, `logbook.core.platform`, `logbook.cli.*` |
| 함수 안 | `rich.*`, `logbook.core.config`, `duration`, `weeks`, `db`, `services`, `models` |
| CLI 어디에서도 금지 | `fastapi`, `uvicorn`, `sqlalchemy` 직접 import, `jinja2`(Phase 4 보고서 명령 본문만 예외), `pyperclip`(core.platform이 이미 지연 import함) |

- **타입 힌트:** 타입용 import는 `if TYPE_CHECKING:` 블록과 문자열 어노테이션으로 쓴다.
- **명령 시그니처:** Typer가 시그니처를 런타임에 평가한다. 따라서 명령 함수에는 런타임에 해석되는 타입(`str`, `bool`, `str | None`, `typer.Context`, `Annotated[...]`)만 쓰고, 명령 모듈에서는 `from __future__ import annotations`를 쓰지 않는다.
- **상수:** `COMMON_SLUG`, `StatsBy` 같은 상수도 CLI 상단에서 services로부터 import하지 않는다.
- **강제 수단:** 이 규칙은 Task 2-4의 서브프로세스 import 가드 테스트가 강제하며, CI의 차단 조건이다. 측정 근거는 다음과 같다.
  - 이 PC에서 `sqlalchemy.orm` import만 0.38~0.43초다.
  - `--version`은 지연 import 시 약 0.16초, 일괄 import 시 약 0.59초다.

### 출력 규칙
- **출력 통로:** 모든 출력은 `cli.console` 함수로만 한다.
- **Console 설정:** Console은 `markup=False, emoji=False, highlight=False`로 만든다. stdout/stderr가 TTY가 아니면 `width=PIPE_WIDTH`(1000), `legacy_windows=False`를 쓴다.
  - Rich 기본 폭은 Windows CI에서 79칸, macOS에서 80칸이다. 고정하면 이 차이와 Windows 전용 렌더 경로가 사라진다.
  - 120 같은 작은 고정 폭에서는 약 50칸이 넘는 메모가 ID와 날짜가 없는 이어진 줄로 접힌다. 그러면 README가 안내하는 `lb log | Select-String payment` 같은 줄 단위 필터가 기록 조각을 돌려주거나 기록을 놓친다. 1000칸이면 메모가 아주 길지 않은 한 기록 한 건이 한 줄이다(실측: 메모 200자 기록도 한 줄).
- **사용자 데이터:** 메모, slug, 프로젝트 이름, 태스크 제목, 설정의 카테고리 라벨은 `rich.text.Text`나 `Text.assemble`로만 출력한다. 사용자 입력이 들어 있는 core 오류 문구도 같다.
  - 그대로 출력하면 생기는 문제(재현함): `fix [/api] route`가 MarkupError를 일으켜 `lb log` 전체가 죽고, `[bold]x[/bold]`는 내용이 바뀐다.
  - `rich.markup.escape`는 쓰지 않는다. 끝의 역슬래시가 두 배가 되고 `:smile:`이 이모지로 바뀐다.
- **줄바꿈:** 한 줄 메시지는 `soft_wrap=True`로 출력한다. 비 TTY에서도 줄이 중간에 끊기지 않는다.
- **스트림 분리:** 결과는 stdout으로, 오류·경고·안내·확인 프롬프트는 stderr로 보낸다.
- **기호:** 모두 `platform.symbol()`로 고른다. cp949는 `✔`와 `—`를 인코딩하지 못한다.
  - 성공: `✔`(대체 `v`, 초록)
  - 안내: `·`(대체 `-`)
  - 메모 앞: `—`(대체 `-`)
- **표 형식:** `box=None`, `pad_edge=False`, 머리글은 굵게, 숫자 열은 오른쪽 정렬한다. 접을 수 있는 열(`overflow="fold"`)에는 반드시 `min_width`를 주고, 나머지 열은 `no_wrap=True`로 둔다.
- **좁은 화면 대체 출력:** `console.required_width(table)`로 표에 필요한 폭을 직접 계산한다.

**`open_database` 동작**
1. `db_path = Path(path).expanduser()`. `db_path.exists()`가 거짓이면 연결하지 않고 `DatabaseNotInitializedError("데이터베이스가 없습니다: {db_path}. 먼저 'lb init'을 실행하세요.")`를 낸다.
   - 파일과 상위 디렉터리를 만들지 않는다.
   - 기존 `current_version`은 없는 경로에 0바이트 파일을 만들었고, 그 뒤에는 `lb project add common`이라는 잘못된 안내가 나왔다.
2. `engine = create_engine_for(db_path)`
3. `found = current_version(engine)`로 버전을 **한 번만** 읽는다. `None`이면(0바이트 파일 또는 스키마 없는 파일) `DatabaseNotInitializedError("데이터베이스가 초기화되지 않았습니다: {db_path}. 먼저 'lb init'을 실행하세요.")`를 낸다.
4. `found`가 호출 시점의 `SCHEMA_VERSION`과 같으면 추가 조회 없이 engine을 반환한다. 다를 때만 `init_db(engine)`를 부른다. 낮으면 대기 중인 마이그레이션을 적용하고, 높으면 기존 LogbookError가 난다.
   - `lb add` 경로의 DB 확인을 연결 1회, 조회 1회로 줄인다(응답 시간 측정 대상 경로).
5. 2~4에서 예외가 나면 `engine.dispose()` 뒤 다시 던진다. 성공하면 engine을 반환하고, dispose는 호출자 책임이다.

**`initialize_database` 동작** (`lb init`의 DB 단계를 core로 옮겨 mypy strict와 core 커버리지 대상에 넣는다)
1. `engine = create_engine_for(path)`. 상위 디렉터리가 없으면 만든다.
2. `previous = current_version(engine)`, `version = init_db(engine)`
3. finally에서 `engine.dispose()`. `InitResult(previous, version)`를 반환한다.

**SQLite 오류 변환**

`getattr(error.orig, "sqlite_errorname", None)`을 `_`로 나눈 앞 두 토큰을 기본 코드로 본다. 예를 들어 `SQLITE_BUSY_SNAPSHOT`은 `SQLITE_BUSY`가 된다. `sqlite_errorname`은 Python 3.11부터 있다.

| 기본 코드 | 결과(`raise 변환 from error`로 `__cause__` 보존) |
|---|---|
| `SQLITE_BUSY`, `SQLITE_LOCKED` | `DatabaseBusyError("데이터베이스를 다른 프로그램이 사용 중입니다: {path}. 잠시 후 다시 시도하세요.")` |
| `SQLITE_READONLY` | `LogbookError("데이터베이스 파일에 쓸 수 없습니다: {path}. 파일이 읽기 전용인지, 쓰기 권한이 있는지 확인하세요.")` |
| `SQLITE_FULL` | `LogbookError("디스크 공간이 부족해 데이터베이스에 쓸 수 없습니다: {path}. 공간을 확보한 뒤 다시 시도하세요.")` |
| 그 밖, 또는 속성 없음 | `None`(원래 예외 유지) |

적용 위치:
- **`current_version`:** `except DatabaseError`에서 기존 문구("데이터베이스 파일을 열 수 없습니다 … 경로와 파일이 올바른지 확인하세요.")보다 먼저 확인한다. EXCLUSIVE 잠금 중에 경로를 확인하라고 잘못 안내하던 문제가 함께 고쳐진다.
- **`_transaction`:** `BEGIN IMMEDIATE`부터 본문(`create_all`, 마이그레이션, 버전 갱신)과 `conn.commit()`까지 전체를 `try/except OperationalError`로 감싸 변환한다. 변환 결과가 `None`이면 원래 예외를 다시 던진다.
- **`session_scope`:** 예외 분기에서 rollback한 뒤, 예외가 `OperationalError`이고 변환 결과가 있으면 그것을 던진다. 아니면 원래 예외를 던진다(서비스의 flush와 commit 모두 이 경로를 지난다).

이렇게 하면 CLI 처리기는 `LogbookError`만 잡으면 되고, CLI 모듈이 `sqlalchemy.exc`를 import하지 않아도 된다.

## 크로스 플랫폼 체크리스트 (Phase 2 전 Task 공통)

- **진입점:** `run()`이 Click 파싱 전에 `ensure_utf8_console()`을 부르고 `prog_name="lb"`, `windows_expand_args=False`를 넘긴다. 이 PC의 실제 저장소 `lb.exe`는 아직 `app`을 직접 부르므로 Task 2-4에서 `[project.scripts]`를 고친 직후 `uv sync`가 필요하다.
- **출력 기호:** `✔`와 `—`는 `platform.symbol()`로 대체 문자를 준다(cp949는 둘 다 인코딩하지 못하고 cp1252는 `—`만 된다). `·`는 두 코드 페이지에서 안전하다.
- **경로:** `pathlib.Path`만 쓰고, 출력은 `Text(str(path))`로 한다. 한글과 공백이 든 경로를 테스트한다.
- **파일 쓰기:** `encoding="utf-8"`과 `newline="\n"`을 명시한다(측정 보고서, 테스트의 config.toml).
- **날짜 포맷:** `strftime`의 `%-d`, `%-m`을 쓰지 않는다. `day_label`과 `full_day`는 직접 포맷한다.
- **외부 명령:** 리스트 인자, `shell=False`, `timeout`을 지정하고, 실행 파일은 `shutil.which`로 찾는다.
- **출력 결정성:** Rich는 비 TTY에서 폭 1000, `legacy_windows=False`다. 테스트는 Typer의 `FORCE_TERMINAL`과 `MAX_WIDTH`를 고정한다. 서브프로세스는 `_TYPER_FORCE_DISABLE_TERMINAL=1`과 `TERMINAL_WIDTH=200`을 넣고, `\r\n`을 정규화한다.
- **표 폭:** 좁은 화면 판정은 `required_width` 계산식으로 하고, 폭을 줄인 테스트는 `assert_fits`와 마지막 열 값으로 잘림을 확인한다.
- **엔진 정리:** 모든 CLI 경로는 `runtime.session`의 finally에서 `engine.dispose()`를 부르고, `initialize_database`는 스스로 dispose한다. 테스트는 `os.replace`로 확인한다. 잠금용 sqlite3 연결은 finally에서 닫고, 읽기 전용 권한은 finally에서 복구한다.
- **파이프 끊김:** Windows는 `BrokenPipeError` 대신 `OSError(EINVAL)`을 낸다. 이 판정은 stdout 쓰기 지점에서만 한다. 테스트에서 stdout을 닫은 뒤에는 `proc.stdout = None`으로 바꾸고 `communicate()`를 부른다.
- **확인 입력:** `isatty`로 분기하지 않고 stdin 한 줄을 읽는다. 한글 자판 입력(`ㅛ`, `ㅛㄷㄴ`)도 받는다.
- **셸 차이:** README에 안내한다: `#`는 따옴표 필수, `-` 메모 앞에는 `--`, PowerShell의 `$`는 작은따옴표, PowerShell 파이프는 `[Console]::OutputEncoding`.

## 설계 결정 요약 (기술 결정, 계획 승인 시 함께 확정)

1. **DB 진입 일원화:** core에 `open_database()`, `initialize_database()`·`InitResult`, `DatabaseNotInitializedError`, `DatabaseBusyError`, `BUSY_TIMEOUT_SECONDS`를 추가한다.
   - `open_database`는 파일을 만들지 않고 `lb init`을 안내한다. 버전을 한 번만 읽고, 낮을 때만 마이그레이션을 적용한다.

2. **SQLite 오류 변환은 core에서:** BUSY/LOCKED/READONLY/FULL을 `current_version`, `_transaction`(BEGIN, 본문, commit 전체), `session_scope`에서 변환한다. 그래서 CLI 처리기는 `LogbookError`만 잡고, CLI가 `sqlalchemy.exc`를 import하지 않는다. EXCLUSIVE 잠금 중 "경로를 확인하세요"로 잘못 안내하던 문제도 함께 고친다.
3. **기록 수정:** `update_worklog(clear_task=)`를 추가하고 수정 경로 전용 문구를 둔다. Phase 2의 `lb add -t`로 잘못 연결한 기록을 고칠 수 있게 된다. Phase 3의 task 흐름과 Phase 5의 `PATCH /api/logs`도 쓴다.
4. **표기 공유:** `weeks.day_label`과 `weeks.week_heading`을 공개해 lb log, lb stats, 보고서(Phase 4), Web(Phase 5)이 같은 표기를 쓰게 한다.
5. **CLI 모듈 구성:** `main / group / console / runtime / render`와 `commands/` 패키지로 나눈다. 옵션, ID 파싱, 확인 프롬프트는 `runtime.py` 하나에 모아 모듈 수를 줄인다. `commands/`는 Phase 3~5의 명령 추가 지점이다. 테스트 도우미는 conftest가 아닌 `helpers.py`에 둔다.
6. **문자열 인자:** 값 인자(시간, 날짜, 주차, ID, `-t`, `--by`)는 모두 `str`로 받아 명령 본문에서 core 파서로 변환한다.
   - 한국어 오류를 유지하기 위해 Typer의 `parser=`, `int`, `Literal`을 쓰지 않는다.
   - 생략 판정은 `is not None`으로 해서 빈 문자열도 한국어 형식 오류가 나게 한다.
   - ID는 1 이상 2⁶³−1 이하(19자리 이하)만 받아 서비스의 OverflowError traceback을 막는다.
7. **출력 결정성:** 비 TTY에서는 폭 1000, `legacy_windows=False`다. 두 OS가 같은 바이트를 내고, 파이프에서 기록 한 건이 한 줄로 유지된다. 좁은 TTY에서는 직접 계산한 필요 폭으로 판정해 표 대신 한 줄 목록을 출력하므로 데이터가 잘리지 않는다. 사용자 데이터는 항상 `Text`로 감싸고 `escape`는 쓰지 않는다.
8. **삭제 확인:** 확인 프롬프트를 직접 구현한다(stderr 프롬프트, stdin readline, y/yes/ㅛ). 거절과 EOF는 아무것도 지우지 않고 exit 1로 끝난다. `lb log rm 5 && …` 같은 스크립트가 삭제되지 않은 것을 성공으로 오인하지 않게 하려는 것이다.
9. **lb add 누적:** 기록한 날짜의 합계를 보여 준다. 오늘 기록이면 SPEC 줄과 글자까지 같은 `오늘 누적`, 다른 날이면 `MM-DD 누적`이다. 소급 기록에서 그날이 얼마나 찼는지 확인하는 것이 목적이고, 추가 비용도 없다(`day_total_minutes(s, log.date)`).
10. **lb log 기본값과 거부 규칙:**
    - 기본 범위는 이번 주다. lb stats와 주간 보고의 단위와 맞춘다.
    - `--week`와 `--date`를 함께 주면 거부한다. 서비스가 AND로 조용히 0건을 내기 때문이다.
    - 하위 명령 앞에 쓴 조회 옵션은 거부한다. 조용히 무시되는 것을 막는다.
    - 카테고리는 key로 표시해 화면 값을 그대로 `-c`에 쓸 수 있게 한다.
11. **lb stats 형식:** `--by`가 없으면 행렬을 보여 준다. 시간 표시는 SPEC 4 규칙(`35h`)과 설정 라벨을 따르고, SPEC 5·7 예시를 이에 맞춰 고친다. 열을 '기타'로 접는 기능은 넣지 않는다(좁은 화면은 대체 출력이 처리한다).
12. **자동완성:** `add_completion=False`로 영어 자동완성 옵션을 숨기고, Phase 7에서 다시 켠다.
13. **mypy 범위:** CLAUDE.md 규칙대로 strict 대상은 `src/logbook/core`만 유지한다. CLI도 타입 힌트는 단다. 넓히려면 CLAUDE.md 변경이 필요하므로 후속 항목으로 둔다.
14. **커버리지:** `--cov=logbook`(core와 cli)로 전체 80%를 보고, CI의 별도 단계에서 core 단독 80%를 강제한다(SPEC 8).
15. **차단 테스트와 비차단 측정:** 서브프로세스 테스트(진입점, UTF-8, Windows 인자, 파이프 끊김, import 가드)는 두 OS CI의 차단 조건이다. 시간 측정은 비차단 보고서로만 하고, 시간 단언은 넣지 않는다.
16. **Ctrl+C:** Typer 기본 동작(exit 130, 메시지 없음)을 따른다.
17. **의존성:** 새 의존성은 없다.
18. **CLI가 쓰는 core 진입점 명시:** "CLI와 Web은 core.services만 호출한다"를 "도메인 동작은 services, DB 연결·설정·입력 파싱은 정해진 core 공개 진입점, SQL·ORM은 금지"로 해석하고, Task 2-12에서 CLAUDE.md·AGENTS.md에 한 줄로 적는다. 규칙의 의도(CLI에 SQL·ORM 없음)는 바뀌지 않는다.

## 후속 항목 (Phase 2 범위 밖, 기록만)

1. **core 오류 문구 정책:** core 문구에 CLI 문법이 들어 있다(`-c dev`, `lb project list`, `lb task list`, `lb init`). 조사도 고정되어 있다(`태스크 #1는`, `프로젝트 'common'가`). Phase 5 Web에도 그대로 노출되므로 그 전에 정책을 정한다.
   - Phase 2에서는 `-t` 오류가 아직 없는 명령 `lb task list`를 안내한다(Phase 3에서 해소).
   - services의 `check_positive_minutes` 문구(`… 1분 이상이어야 합니다.`)에는 입력 예시가 없다. CLI는 `parse_duration`을 먼저 거쳐 닿지 않지만, Web의 JSON API는 닿을 수 있다.
2. **날짜 입력 엣지:** `MM-DD`는 항상 올해로 해석된다(연초에 작년 날짜를 넣으면 미래 날짜가 된다). 미래 날짜와 하루 합계 24시간 초과도 막지 않는다. 필요하면 core 규칙은 그대로 두고 stderr 경고만 추가한다.
3. **동시 쓰기:** Phase 5에서 `lb serve`와 CLI가 동시에 쓰면 쓰기 잠금 충돌 시 최대 5초를 기다린다. 그때 WAL 모드와 대기 시간을 다시 본다(`BUSY_TIMEOUT_SECONDS` 재사용).
4. **마이그레이션 백업:** `open_database`는 버전이 낮으면 어느 명령에서든 대기 중 마이그레이션을 적용한다. 첫 실제 마이그레이션(Phase 6 `week_notes`)에 적용 전 백업을 함께 넣는다.
5. **mypy 범위:** strict를 `src/logbook/cli`로 넓힐지 정한다(CLAUDE.md와 CI 변경 필요).
6. **typer 상한:** `typer>=0.16`에 상한이 없다. 테스트 fixture가 `typer.rich_utils.FORCE_TERMINAL`과 `MAX_WIDTH`에 의존하므로 상한을 고정할지 정한다(의존성 명세 변경이라 승인 필요). 고정한다면 D1의 help 틀 한글화도 다시 검토한다.
7. **Python 3.11 CI:** CI에 3.11을 추가할지 정한다. 3.11은 Windows에서 `platform.machine()` 비용 때문에 SQLAlchemy import가 더 느리다.
8. **D2 미채택 시:** 프로젝트 보관 해제(`lb project unarchive` 또는 Phase 6 `/settings`)를 후속으로 둔다.
9. **메모 여러 단어 입력:** SPEC 5대로 메모는 따옴표로 감싼 한 인자만 받는다. 따옴표 없이 남는 단어를 이어 붙이는 방식(`note: list[str]`)은 `-p`를 빠뜨린 단어가 메모에 조용히 섞이는 위험이 있어 넣지 않는다. 요청이 있으면 별도로 정한다(따옴표 사용법은 그대로 동작하므로 나중에 바꾸기 쉽다).
10. **메모 안의 줄바꿈:** core가 메모 안의 줄바꿈을 막지 않아, 그런 기록은 표와 한 줄 목록에서 여러 줄이 된다. 필요하면 core `_clean_note`에서 거부하거나 공백으로 바꾼다.
11. **SPEC 7 보고서 표 열 이름:** 보고서 표의 `리뷰`·`기타`를 설정 라벨(`코드리뷰`·`행정/기타`)과 맞출지 Phase 4에서 템플릿과 함께 정한다.
12. **Phase 7:** `-h` 도움말 별칭, 셸 자동완성(`add_completion` 복구)
