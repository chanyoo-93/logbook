> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 비어 있거나 실패한 화면이 "다음에 무엇을 하면 되는지"를 웹의 말로 알려 준다.

다룰 것은 세 가지다.
1. **2026-10-26 전 화면 평가 P2:** 빈 상태와 오류 페이지가 다음 행동을 알려 주지 않는다.
   - 태스크 보드 열은 `없습니다.`, 계획은 `계획된 태스크가 없습니다.`만 쓴다.
   - 404 등 오류 페이지는 머리·메뉴가 없는 막다른 화면이고, CLI 명령(`lb task list`)을 안내한다.
2. **PR #31 QA 참고 b:** 웹 오류 문구에 CLI 안내가 섞인다. SPEC 7장 "웹 전용 오류 문구"에 후속 항목으로 이미 올라 있다.
   - 예: `버리려면 'lb cancel'을 실행하세요.` 화면에는 `취소` 버튼이 있다.
3. **PR #31 QA 참고 a:** 진행 중 타이머의 `정지`가 실패하면 포커스가 페이지 맨 앞으로 간다.
   - 1분 미만이거나 충돌하는 경우다.
   - 원인은 `app.js` 포커스 규칙이다. 4xx 응답에서는 편집 중이거나 `data-refocus`인 대상에만 포커스를 준다.

**기준:** PR #31 병합 뒤 develop에서 갈라질 브랜치 `feat/empty-states-errors`. 계획서는 병합 전에 미리 썼다.

- 계획서 승인 → Task 순서대로 진행한다. 테스트를 먼저 써서 실패를 확인(RED)한다.
- Task마다 전후 스크린샷을 보여 주고 사용자 승인을 받는다.

## 설계

### 웹 문구(G1)

- `core/errors.py`: `LogbookError.__init__(self, message: str, *, web_message: str | None = None)`. 웹 문구는 `error.web_message` 속성으로 둔다. `str(error)`는 지금처럼 CLI 문구다.
- `web/errors.py`: `user_message(error: LogbookError) -> str`를 둔다. 웹 문구가 있으면 그것을, 없으면 `str(error)`를 돌려준다.
  - 화면 응답(오류 페이지, HTMX 알림, 각 페이지의 폼·패널 오류 줄)의 `str(error)` 17곳을 이 함수로 바꾼다.
  - `/api/` JSON 응답은 CLI 문구를 그대로 둔다. API를 쓰는 쪽은 스크립트이고, CLI 명령 안내가 맞다.
- 웹 문구를 붙일 오류(웹에 나올 수 있는 것만). DB 초기화·`lb import`·`lb serve` 문구는 웹에 나오지 않거나 서버 안내라 그대로 둔다.

### 빈 상태(G2)

| 위치 | 지금 | 바꿀 문구(링크는 [ ]) |
|---|---|---|
| 태스크 보드 할 일 열 | `없습니다.` | `할 일이 없습니다. [새 태스크]로 추가하세요.` |
| 태스크 보드 진행 중 열 | `없습니다.` | `진행할 태스크를 여기로 끌어 오면 진행 중이 됩니다.` |
| 태스크 보드 완료 열 | `없습니다.` | `완료한 태스크를 여기로 끌어 오세요.` |
| 태스크 보드 중단 열 | `없습니다.` | `중단할 태스크를 여기로 끌어 오세요.` |
| 태스크 다음 주 계획 | `계획된 태스크가 없습니다.` | `계획한 태스크가 없습니다. [새 태스크]에서 계획 주를 정하세요.` |
| 대시보드 최근 기록 | `기록이 없습니다.` | `아직 기록이 없습니다. 위에서 시간과 메모를 넣고 기록하세요.` |
| 대시보드 주간 요약 | `이번 주 기록이 없습니다.` | `이번 주 기록이 없습니다. 기록하면 요일별·프로젝트별 공수가 여기에 보입니다.` |
| 기록 화면 표 | `기록이 없습니다.` | 필터가 있으면 `조건에 맞는 기록이 없습니다. 주차나 필터를 바꿔 보세요.`, 없으면 `이 주에는 기록이 없습니다. [대시보드]에서 기록하세요.` |

- 보고서 표 보기의 자리표시 문구(`(작성하세요)` 등)는 보고서 내용이라 그대로 둔다.
- 링크 모양은 본문 링크(`--accent`)이고, 보드 빈 칸은 끌어 놓기 대상이 그대로 되게 목록 항목 안에 둔다.

### 오류 페이지(G3)

- `templates/error.html`이 `base.html`을 잇는다. `base.html`의 `current_week`·`config_notice`는 `default`로 받아 없으면 빼게 바꾼다.
  - 오류 페이지는 `_shared_context`를 쓰지 않는다. DB·설정을 읽지 않는다.
- 머리 메뉴의 현재 화면 표시(`aria-current`)는 요청 경로의 첫 마디로 정한다(`/tasks/99` → 태스크).
- 본문:
  - 오류 문구(`role="alert"`)를 카드(`.panel`)로 보인다.
  - 링크 둘: 관련 화면(경로 첫 마디가 tasks·logs·report·settings면 그 화면으로 가는 `태스크 화면으로` 등)과 `대시보드로`.
  - 숨긴 h1 `오류`는 그대로다.
- 템플릿 렌더링이 실패하면(500 처리 안에서 또 실패하면) 지금의 최소 문자열 페이지로 대신한다.
- HTMX 알림 조각과 API 봉투는 그대로다.
